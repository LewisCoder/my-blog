# Mission: 用 AI 重构 Java 后端开发工作流

## Why
我是一名后端 Java 程序员，想把日常的「工单 → 代码 → 测试 → 文档/Review」整条链路改造成一套半自动的 AI 工作流，减少写样板代码、补测试和重复沟通的耗时。先在个人项目上跑通，公司对 AI 工具的政策明确后再迁移到工作。

## Success looks like
- 在至少 3 个小功能上跑通完整闭环：工单 → 规格/计划 → 实现 → 测试通过 → 自动生成的改动说明或 Review 意见。
- 拥有一套固定资产（工单模板、CLAUDE.md 规则、验证命令），不需要每次从零构思提示词。
- 用 `claude -p`、hooks 或 CI 把至少一个环节（如测试生成或代码评审）变成一条命令即可执行。
- 能在 30 分钟内判断一份 AI 产出是否可信——依据测试与验收标准，而不是通读全部代码。

## Constraints
- 技术栈以后端 Java 为主；每周可投入 2–5 小时。
- 公司能否使用外部云 AI 尚未确认，因此练习场是个人 Java 项目，所学流程需可迁移到内网模型场景。
- 已在用 Claude Code；仓库已配置 OpenSpec。
- 课程用中文授课；单课控制在 20–40 分钟内。

## Out of scope
- 调试与排障的自动化（当前优先写码、测试、文档/评审）。
- 把 LLM 能力做进业务服务（RAG、Agent 产品功能）——那是另一个 mission。
