AI 工作流 · Java 后端 · 第 1 课

写一张 Agent 能执行的工单

约 25 分钟 · 2 个练习 · 需要：一个你自己的 Java 小项目 + Claude Code
参考卡片：AI 开发流水线 · 词汇表：课程术语

本课要赢得的 把一个模糊需求写成一张可执行工单，并让 Claude 只回一份你能逐条审阅的计划。 这两样东西是你整条 AI 流水线的输入和第一道闸门。

为什么从工单开始

你要建的流水线是「工单 → 规格/计划 → 实现 → 测试 → 文档/评审」。这条流水线有一个特点：后面每一步的质量上限，由最前面那张工单决定。

Anthropic 在官方最佳实践里把 Agent 偏离预期的原因归结为两类：Claude 缺少它无法从代码里读到的信息，或者它没有可运行的检查来证明自己做对了（Best practices for Claude Code）。工单恰好就是写这两件事的地方——把约束写下来，把验收标准写成检查。

你已经用 OpenSpec 写过 proposal（仓库里的 openspec/changes/add-blog-search/ 就是一份），那属于流水线的第②阶段。但 proposal 的上游是工单：如果工单里的目标、验收标准和边界是松的，proposal 再精致也只是在放大模糊。

整条流水线长什么样

  1. 工单
  2. 规格与计划
  3. 实现
  4. 验证
  5. 评审与文档

每个阶段都有自己的闸门（过关条件）。第①阶段的闸门只有一条：每条验收标准都能对应一个测试或命令。做不到这一条，后面的 Agent 就只能靠猜，或者靠自我声明「完成了」。完整的阶段地图、模板和提示词都在 流水线参考卡片 里。

可执行工单的五要素

要素回答的问题反例
目标为什么做，业务结果是什么「优化任务模块」
验收标准完成时能观察到什么，怎么验证「功能完善，体验良好」
范围边界本次做什么、明确不做什么只写「做」，不写「不做」
约束技术栈、风格、不能碰什么、必须运行的命令让 Agent 自行挑选新依赖
验证方式用哪条命令判定「完成」「请确认功能正常」

验收标准怎么写

统一成这个句式，写不出来的就说明还没想清楚：

当 <触发条件> 时，<系统> 应 <可观察结果>；可由 <测试/命令> 验证。

反例与改写（Java）

反例：「任务创建功能完善，参数校验合理，体验良好。」

改写：

  • 当 POST /api/tasks 收到 {"title":"买菜"} 时，应返回 201，响应体含 id 与 createdAt；由 TaskControllerTest 验证。
  • 当请求缺少 title 时，应返回 400，错误码为 TITLE_REQUIRED；由 TaskControllerTest 验证。
  • 以上行为在 mvn -q test -Dtest=TaskControllerTest 下必须全部通过。
写不出验证命令？ 说明这个需求对当前这一版来说太大或太模糊。把它拆小、砍掉主观描述，直到每条标准都能被一条命令检查。 独立评估机构 Thoughtworks 也提醒：规格容易越写越长、越来越难审，小而硬的工单比完备的文档更可靠（技术雷达）。

练习 A · 判断力训练

下面每道题选一个答案，作答后立即看到解释。凭直觉选，选错比选对更有价值。

1. 以下哪条验收标准最适合交给 Agent 执行？

2. 工单里「不做」这一节，最重要的作用是什么？

3. 让 Agent 写代码之前先交计划，最大的好处是什么？

练习 B · 把真实需求过一遍

现在用你自己的项目，跑一遍流水线的第①→②阶段。整个过程只到「计划」为止，不写代码。

步骤

  1. 选需求：挑一个半天内能完成的小功能，例如「新增一个只读接口」「给列表加分页参数」。若来自工作，先去掉业务敏感信息。
  2. 写工单：按 模板 填五要素，写进 docs/tickets/0001.md 之类的位置。
  3. 只换计划：在练习项目的 Claude Code 会话里粘贴下面这段提示词，附上你的工单。
  4. 逐条审阅：检查每条验收标准是否都有对应验证、是否越界。你至少要提出一处修改——这才是真正的审阅。

提示词（直接复制）

下面是我的工单。先只输出实施计划：不要修改任何文件，也不要开始实现。

计划必须包含：
1. 逐条复述验收标准，并写明每一条打算用什么测试或命令验证；
2. 要修改/新增的文件清单与实施顺序；
3. 工单里没说清、需要我先确认的问题；
4. 你注意到的、但超出工单范围的隐患（只列出，不要动手）。

工单如下：
<粘贴你的工单>
本课的可交付物 一份你审过、改过的计划（哪怕只改了一行），以及对应的一张工单。把它们保存在项目里，下一课会从这份计划接着往下走。

完成检查

  • 工单能在一屏内读完。
  • 每条验收标准都能对应至少一个测试或命令。
  • 「不做」至少写了一条。
  • 计划覆盖了全部验收标准。
  • 你在计划中至少提出并落实了一处修改。

推荐一手资料

本课主要依据 Best practices for Claude Code（Anthropic 官方）。今天只读两节：

  • Tell Claude what it can't see —— 为什么具体提示词与项目上下文是前提；
  • Give Claude a check to run —— 为什么可运行的检查比文字说明更可靠。
