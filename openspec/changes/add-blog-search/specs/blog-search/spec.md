# Spec Delta

## Purpose

站内搜索让读者不必离开当前页面，就能用查询词直接定位文章正文中的内容。它覆盖已发布文章的标题、摘要、标签与正文，并在浏览器本地完成匹配、排序与结果呈现。搜索以页头唤出的浮层承载，不占用独立页面。

## ADDED Requirements

### Requirement: 搜索入口

站点 MUST NOT 提供独立搜索页。站点 MUST 在页头提供搜索按钮，并在任意页面（首页、文章列表、文章详情、标签、关于、404）唤出同一个搜索浮层。浮层 MUST 可通过点击页头搜索按钮或 `Ctrl+K`（macOS 为 `⌘K`）打开，并可通过 `Esc`、浮层内关闭按钮或点击遮罩关闭；关闭后 MUST 回到打开前的页面与位置，不发生页面跳转。

#### Scenario: 从任意页面打开浮层

- **WHEN** 访问者在任意页面点击页头「搜索」按钮
- **THEN** 当前页面弹出搜索浮层，输入框获得焦点，页面不发生跳转

#### Scenario: 快捷键打开

- **WHEN** 访问者按下 `Ctrl+K` 或 `⌘K`
- **THEN** 搜索浮层打开并聚焦输入框；再次按下快捷键时浮层关闭

#### Scenario: 关闭回到原页面

- **WHEN** 浮层打开时访问者按下 `Esc`、点击关闭按钮或点击遮罩
- **THEN** 浮层关闭，焦点回到页头搜索按钮，页面内容与滚动位置保持不变

#### Scenario: 不存在独立搜索页

- **WHEN** 访问者直接访问 `/search/`
- **THEN** 站点不提供该页面（404），搜索仅通过浮层使用

### Requirement: 索引内容边界

搜索索引 MUST 只包含已发布文章；`draft: true` 的草稿、`/about/` 等非文章页面 MUST NOT 出现在搜索结果中。

#### Scenario: 草稿不可被搜索

- **WHEN** 一篇草稿含有某唯一查询词，访问者搜索该查询词
- **THEN** 结果中不出现该草稿

#### Scenario: 非文章页面不可被搜索

- **WHEN** 某查询词只出现在「关于」页而非任何已发布文章
- **THEN** 搜索结果为空

### Requirement: 可搜索字段

每篇已发布文章的标题、摘要、标签与正文 MUST 参与搜索；正文中的代码标识符 MUST 保留并可被命中。

#### Scenario: 正文术语命中

- **WHEN** 访问者搜索一个只出现在某篇文章正文中的中文术语
- **THEN** 该文章出现在结果中

#### Scenario: 代码标识符命中

- **WHEN** 访问者搜索一个只出现在某篇文章代码块中的标识符
- **THEN** 该文章出现在结果中

#### Scenario: 标签命中

- **WHEN** 访问者搜索一个仅作为标签存在的词
- **THEN** 带有该标签的文章出现在结果中

### Requirement: 中文查询匹配

系统 MUST 在无需空格分隔的情况下匹配中文查询；查询被分词后，所有查询词 MUST 同时出现在同一篇文章的可搜索字段中才算命中。

#### Scenario: 无空格中文查询

- **WHEN** 访问者输入「智能」且文章正文包含「智能客服」
- **THEN** 该文章命中

#### Scenario: 多词全部命中

- **WHEN** 访问者输入「Agent 面试」，某文章同时含「Agent」与「面试」
- **THEN** 该文章出现在结果中

#### Scenario: 部分词不命中则排除

- **WHEN** 访问者输入「Agent 面试」，某文章只含「Agent」而不含「面试」
- **THEN** 该文章不出现在结果中

### Requirement: 查询归一化

查询匹配 MUST 忽略拉丁字母大小写，并将全角与半角字符视为等价；该归一化 MUST 同时作用于查询与文章内容两侧。

#### Scenario: 大小写不敏感

- **WHEN** 访问者输入「agent」而文章写作「Agent」
- **THEN** 该文章命中

#### Scenario: 全角半角等价

- **WHEN** 访问者输入全角「ＡＧＥＮＴ」
- **THEN** 结果与输入半角「AGENT」一致

#### Scenario: 正文全角同样可匹配

- **WHEN** 文章正文写作全角「ＡＧＥＮＴ」而访问者输入半角「AGENT」
- **THEN** 该文章命中

### Requirement: 结果排序

搜索结果 MUST 按相关度降序排列：标题命中权重最高，其次为标签、摘要、正文；相关度相同的文章 MUST 按发布日期从新到旧排列；发布日期也相同时 MUST 按文章 id 升序排列，保证同一查询的结果顺序稳定。

#### Scenario: 标题命中优先

- **WHEN** 某查询同时命中文章 A 的标题与文章 B 的正文
- **THEN** 文章 A 排在文章 B 之前

#### Scenario: 同分按日期排序

- **WHEN** 两篇文章的相关度得分相同
- **THEN** 发布日期较新的文章排在前面

#### Scenario: 日期相同按 id 稳定排序

- **WHEN** 两篇文章的相关度与发布日期都相同
- **THEN** 文章 id 较小者排在前面，且同一查询重复执行时顺序一致

### Requirement: 结果呈现

每条结果 MUST 在浮层内展示标题、发布日期、标签与上下文文本，并对命中词做高亮。上下文文本 MUST 优先截取正文命中位置前后约 60–80 个字符；正文无命中而标题或标签命中时，MUST 改用文章摘要作为上下文。标题与标签中的命中 MUST 同样高亮。浮层 MUST 高亮当前选中结果，每条结果 MUST 可点击进入对应文章。

#### Scenario: 摘要围绕命中位置

- **WHEN** 访问者在文章中部命中查询词
- **THEN** 结果上下文包含该查询词及其前后文，而不是文章开头

#### Scenario: 仅标签命中时使用文章摘要

- **WHEN** 查询词只出现在文章的标签中（如「求职」），正文与摘要均无该词
- **THEN** 结果以上下文形式展示该文章的摘要，并高亮标签中的命中词

#### Scenario: 点击结果进入文章

- **WHEN** 访问者点击一条搜索结果
- **THEN** 浮层关闭并进入该文章的详情页

### Requirement: 高亮安全

命中高亮 MUST 先将文章内容做 HTML 转义，再插入高亮标记；查询词中的 HTML 或脚本片段 MUST NOT 被解析或执行。

#### Scenario: 查询词包含 HTML

- **WHEN** 访问者输入包含 `<script>` 或尖括号的查询词且文章含相同文本
- **THEN** 页面显示其文本形式，不执行也不构造对应元素

#### Scenario: 正常高亮

- **WHEN** 命中词出现在标题、标签或上下文中
- **THEN** 该词以高亮样式呈现，其余文本保持原样

### Requirement: 浮层状态文案

搜索浮层 MUST 在空查询、索引加载中、无结果三种状态下显示明确的终端风格提示文案；索引加载失败时 MUST 显示错误提示与重试入口。

#### Scenario: 空查询

- **WHEN** 浮层打开且输入框为空
- **THEN** 显示引导输入查询词的提示，不显示结果列表

#### Scenario: 无结果

- **WHEN** 查询没有命中任何文章
- **THEN** 显示无匹配结果的提示

#### Scenario: 加载中

- **WHEN** 索引尚未加载完成且访问者已开始输入
- **THEN** 显示索引加载中的提示

#### Scenario: 加载失败可重试

- **WHEN** 索引请求失败
- **THEN** 显示加载失败提示；点击重试后重新请求索引并执行当前查询

### Requirement: 查询深链

查询内容 MUST 同步到当前页面 URL 的 `q` 参数，长度 MUST NOT 超过 120 个字符。打开带 `q` 参数的任意页面时，MUST 自动唤出搜索浮层并立即加载索引执行查询；`q` 超出长度上限时 MUST 先截断再执行。关闭浮层时 MUST 移除 `q` 参数，避免刷新页面时重复弹出。

#### Scenario: 输入同步到 URL

- **WHEN** 访问者在浮层中输入查询词
- **THEN** 当前页面 URL 的 `q` 参数更新为该查询词

#### Scenario: 打开深链

- **WHEN** 访问者打开 `/blog/?q=智能` 或 `/?q=智能`
- **THEN** 页面自动唤出浮层并显示「智能」的查询结果

#### Scenario: 超长查询被截断

- **WHEN** 访问者打开 `q` 参数超过 120 个字符的链接
- **THEN** 系统只对截断后的前 120 个字符执行查询

#### Scenario: 关闭后清理深链

- **WHEN** 访问者关闭浮层
- **THEN** 当前 URL 不再包含 `q` 参数

### Requirement: 键盘交互

搜索浮层 MUST 支持 `↑`/`↓` 在结果间循环移动选中项、`Enter` 打开当前选中结果、`Esc` 关闭浮层并把焦点还给页头搜索按钮；每条结果 MUST 是可通过 Tab 聚焦的原生链接。

#### Scenario: 方向键选择

- **WHEN** 输入框聚焦且已有结果，访问者按 `↓`
- **THEN** 选中项下移一条；到达末尾后回到第一条，按 `↑` 反向循环

#### Scenario: Enter 打开选中结果

- **WHEN** 已有结果且访问者按 Enter
- **THEN** 打开当前选中结果对应的文章

#### Scenario: Esc 关闭

- **WHEN** 浮层打开，访问者按 Esc
- **THEN** 浮层关闭，焦点回到页头搜索按钮

#### Scenario: Tab 聚焦结果

- **WHEN** 访问者从输入框按 Tab
- **THEN** 焦点移动到第一条结果链接

### Requirement: 本地执行与性能

搜索 MUST 在浏览器本地完成，运行时 MUST NOT 依赖后端或第三方搜索服务。索引 MUST 在浮层打开或首次输入后才开始请求（带 `q` 参数的深链视为打开浮层），且构建产物的索引传输体积 MUST NOT 超过 30KB（gzip）。

#### Scenario: 未交互不加载索引

- **WHEN** 访问者打开任意页面但从未打开搜索浮层
- **THEN** 浏览器不请求搜索索引

#### Scenario: 打开浮层加载索引

- **WHEN** 访问者打开搜索浮层
- **THEN** 索引被预加载一次并缓存供后续查询复用

#### Scenario: 索引体积预算

- **WHEN** 执行生产构建
- **THEN** 搜索索引的 gzip 体积不超过 30KB

### Requirement: 既有输出不受影响

启用搜索后，现有文章列表、标签页与 RSS 的路径和内容 MUST 保持原有行为；独立搜索页 MUST NOT 再生成，sitemap MUST NOT 包含 `/search/`。草稿 MUST NOT 进入这些输出。

#### Scenario: 既有路由保持

- **WHEN** 执行生产构建
- **THEN** 既有的列表、标签、文章与 RSS 路由均照常生成，且不生成 `/search/`

#### Scenario: 草稿仍被排除

- **WHEN** 存在 `draft: true` 的文章
- **THEN** 它仍不出现在列表、标签页与 RSS 中
